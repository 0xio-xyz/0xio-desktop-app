# Rust core

The Rust side of 0xio Desktop (`src-tauri/`). It is the only part that holds keys, the only part that signs, and the gate every window goes through. The app starts in `src-tauri/src/main.rs` and is set up in `src-tauri/src/lib.rs`, which registers the plugins and lists every command.

## Where the code lives

| Path | What it does |
|------|--------------|
| `src-tauri/src/lib.rs` | Plugins, the command list, window events, the proof thread pool size, logs |
| `src-tauri/src/state.rs` | Shared state: the app's PVAC context, the extension's PVAC context and its connection, socket counters |
| `src-tauri/src/wallet/wallet_commands.rs` | Vault, create, import, derive, unlock and lock, idle lock, signing, export |
| `src-tauri/src/wallet/touch_id.rs` | The macOS keychain item that holds the password for Touch ID |
| `src-tauri/src/wallet/secret_clipboard.rs` | Copying a phrase or key: this computer only, hidden from clipboard managers, cleared after 60 seconds unless something else was copied since |
| `src-tauri/src/pvac/pvac_commands.rs` | PVAC encrypt, decrypt, commitments and proofs |
| `src-tauri/src/pvac/proof_pool.rs` | The Rayon pool proofs run on |
| `src-tauri/src/pvac/stealth.rs` | Matching stealth outputs with the wallet's key |
| `src-tauri/src/ws/` | Local socket (`ws_server.rs`), pairing and who may connect (`ws_auth.rs`), the site queue (`ws_sites.rs`) |
| `src-tauri/src/sites/` | Site records and request lifecycle (`site_lifecycle.rs`), relayed sites (`site_relay.rs`), direct sites (`site_direct.rs`), browser frame requests (`site_frames.rs`), sandboxed frames (`frame_protocol.rs`), Circle file picks (`circle_pick.rs`), notifications (`site_notify.rs`) |
| `src-tauri/src/dapp/` | dApp windows (`window.rs`), their injected provider (`provider.rs`), the bridge to the main window (`bridge.rs`) |
| `src-tauri/src/net/` | Node RPC posts (`node_rpc.rs`), NFT media fetch (`nft_fetch.rs`) |
| `src-tauri/src/guard/` | Window checks (`ipc_guard.rs`), command access tests (`command_guard.rs`) |
| `src-tauri/src/system/` | Menu bar (`tray.rs`), open at login (`autostart.rs`), one copy at a time (`single_instance.rs`), contract workspace files (`workspace_commands.rs`), window colour before paint (`window_look.rs`), daily logs (`log_file.rs`), atomic writes (`atomic_file.rs`) |
| `src-tauri/capabilities/`, `src-tauri/permissions/` | What each window may call |
| `src-tauri/tauri.conf.json` | Windows, CSP, bundle and updater settings |

| Group | Commands | Granted to |

| Touch ID | `touch_id_state`, `touch_id_store`, `touch_id_read`, `touch_id_clear` | Main window |
| PVAC | `pvac_*`, `stealth_match_outputs` | Main window |
| Network | `node_rpc_post`, `nft_fetch` | Main window |
| Pairing | `ws_pair_*`, `ws_paired_list` | Main window |
| Sites | `site_list`, `site_review_open`, `site_stage`, `site_respond`, `site_progress`, `site_frame_*`, `site_wallet_hello`, `site_disconnect`, `site_send_event`, `site_lock_event`, `site_notify_*`, `notice_post` | Main window |
| Site reviews | `site_queue`, `site_answer`, `site_reject` | Menu bar panel |
| Frames and Circles | `stage_frame_document`, `stage_frame_asset`, `circle_pick`, `circle_read_picked` | Main window |
| dApp windows | `dapp_open_window`, `dapp_bridge_respond`, `dapp_set_windows_hidden`, `dapp_emit_event` | Main window |
| dApp bridge | `dapp_bridge_request` | dApp windows only |
| Menu bar | `tray_publish`, `tray_progress`, `tray_auth_hold`, `main_close_hold` | Main window |
| Menu bar panel | `tray_get_state`, `tray_action`, `tray_unlock`, `tray_approve_send`, `tray_hide` | Menu bar panel |
| Workspace | `workspace_list`, `workspace_read`, `workspace_write`, `workspace_mkdir`, `workspace_delete`, `workspace_rename` | Main window |
| System | `system_info`, `set_proof_threads`, `get_log_path`, `open_log_folder`, `frontend_log`, `restart_app`, `window_theme` | Main window |

The exact grants are `src-tauri/permissions/main-window.toml`, `tray-window.toml` and `capabilities/dapp.json`. The per-command permission files in `permissions/autogenerated/` are generated by the build from the command list in `src-tauri/build.rs`, which must match the handler list in `lib.rs`: a command missing there is denied in every window.

## Menu bar

`src-tauri/src/system/tray.rs` owns the icon, a short native menu and the panel window. The main window stays the only owner of wallet state: it publishes a snapshot (`tray_publish`), the panel reads it (`tray_get_state` and the `tray-state` event) and asks for changes (`tray_action`), which go back to the main window to run its own code. A password typed in the panel is checked in Rust and never travels to another window.

Closing the main window (red button, Cmd W or Cmd Q) hides it and keeps the app in the menu bar with no Dock icon; Quit in the menu bar menu or panel is the only way to quit. A second launch shows the running window and exits (`single_instance.rs`; a dev build keeps its own copy). Open at login uses a per-user LaunchAgent on macOS and the per-user Run key on Windows, and starts in the menu bar.

## Files

All in the app data folder (`com.0xio.desktop`):

| File | Holds |
|------|-------|
| `vault.json`, `vault.json.bak` | The sealed wallets and the previous copy |
| `ws_pairings.json` | Paired extensions and programs, and the connection settings |
| `ws_sites.json` | Connected sites per network and address, and the hashes of site tokens |
| `logs/` | Daily log files; Settings shows their size and opens the folder |

Files that hold wallet or site state are written atomically and readable by this user only. The contract workspace (`workspace_*`) reads and writes only inside the folder the user picked; every path is checked again against that root.

## Rules

- A command that touches keys, the vault, the workspace or windows checks its caller with `require_main`, even though the capability already limits it.
- A new command is added to `lib.rs` and `build.rs`, listed in `src-tauri/permissions/` and granted only to the window that needs it, never to a window that loads remote content. `command_guard.rs` must still pass.
- Lock zeroizes the session password and the vault key held in memory.
- No new crate without a maintainer's agreement first; prefer a small helper.
- Run `cd src-tauri && cargo test` (needs the privacy engine crates) before a pull request.
